# 省 token 与微信 / QQ 回复

## 聊天不要走完整 Agent

任务型 Agent 每一步都要：系统人设、节点列表、历史、决策、工具结果。适合“打开设置”“看看屏幕”，不适合“在吗”“晚安”。

现在分两条路：

```text
收到消息
  ├─ 在吗/你好/早安/晚安/哈哈/谢谢/收到 → 罐头回复（0 token）
  ├─ /do … 或“帮我打开/去看看/查一下…” → 任务 Agent
  └─ 其他 → Fast Chat（一次模型调用）
```

## Fast Chat

```text
system: 短人设 + 当前渠道（微信/QQ）
history: 最近 4 条
max_tokens: 100
thinking: disabled
memory: 默认不注入；只有“记得/上次/之前/日记”等才召回
```

和旧版相比：

- 不再先用一次 LLM 判断“聊天还是任务”
- 不再每条都塞 10 条历史、14 天记忆和 12 行日记
- 不再默认开 thinking
- 回复限制在 300 字以内

普通闲聊通常能降到几百 token；能命中罐头就是 0。

## 微信 / QQ 推荐接法

### 方案 A：channel bridge + ntfy（推荐，手机保持独立）

```text
微信/QQ
  → 官方机器人 / 企业微信 / 你已有的 bridge
  → POST https://ntfy.envs.net/<topic>
     Tags: wechat,private  或  qq,group
  → 手机 Fast Chat
  → 回复消息 Tags: whale
  → bridge 轮询后发回微信/QQ
```

标签约定：

| 标签 | 含义 |
|---|---|
| `wechat` | 来自微信 |
| `qq` | 来自 QQ |
| `group` | 群聊；没 @ 大肥鱼就跳过 |
| `private` | 私聊 |
| `whale` | 大肥鱼的回复，bridge 只取这类 |

群聊规则已经写在 agent 里：`group` 且正文没有 `@` 或“大肥鱼”时，不回复、不花 token。

### 方案 B：QQ 官方机器人

QQ 开放平台的官方机器人有 WebSocket/回调，不需要动个人 QQ。  
需要一个常驻进程；可以放在小服务器，也可以尝试在手机上跑 WebSocket 客户端，但稳定性不如服务器。

### 方案 C：企业微信 / 公众号

企业微信自建应用、公众号客服接口都是官方通道。  
需要公网回调地址和审核，适合长期用，不适合五分钟搭一个。

### 方案 D：个人微信/QQ UI 自动化

技术上可以用无障碍点微信/QQ，但不建议：

- 违反平台规则，可能封号
- 需要读屏/点按，慢且容易误触
- 账号风控会盯自动化行为

如果一定要做，只用独立小号、独立手机，不要碰主号。

## 为什么不让手机直接登微信/QQ

- 微信在项目的 `DENY_PACKAGES` 里，默认禁止打开
- 手机 agent 的强项是“控制这台手机”，不是“做 IM 网关”
- 把微信/QQ 放在 bridge 层，手机只负责“怎么回”，职责更清楚
- bridge 可以决定哪些群、哪些人、什么时间才转发，省 token 也省风险

## 配置

Fast Chat 目前无需额外开关，默认生效。  
想临时让某句话走任务，发：

```text
/do 打开设置
```

不要用“帮我看看…”来测试闲聊，它会被判定成任务。
